# AI 动态分镜脚本工作台 V2.0 · 首个测试版

本分支 `dev/v2-workbench` 用于开发测试。正式网页继续由 `main` 提供，未修改 Pages 设置，未合并到 main。

## 开发版预览

需要 Node.js 20 或更新版本。**运行应用无需安装依赖，也无需 API Key。**

```sh
git clone --branch dev/v2-workbench https://github.com/zhonghongtao1014-cell/storyboard-motion-studio.git
cd storyboard-motion-studio
node scripts/serve.mjs
```

打开 <http://127.0.0.1:4173>。停止预览时在终端按 Ctrl+C。端口占用时设置 `PORT` 环境变量后重新启动。

也可以下载该分支 ZIP，解压后在文件夹内运行 `node scripts/serve.mjs`。V2 使用模块脚本，不能直接双击 HTML 运行。自带的静态服务器只监听本机，不会修改正式网站。

## 本版可测试的流程

1. **脚本导入**：粘贴文本，或上传 TXT、Markdown、CSV、DOCX、Fountain。UTF-8 和常见 GB18030 文本可读取。优先按 `镜头01` / `SHOT 01` 等镜号拆分，无镜号时按空行拆分；Markdown 表格也可识别。
2. **检查拆镜预览**：提取场景、画面、动作、对白/旁白、时长、景别、机位和运镜。用户确认后追加或替换项目镜头，支持撤销。每个项目最多 200 镜。
3. **镜头总览**：卡片显示缩略图、镜号、描述、时长和状态；汇总总时长，按未生成、已生成、已确认、待修改筛选。
4. **逐镜编辑**：各镜独立保存文案、备注、素材、参数和主体选区。支持上一镜/下一镜、复制、新增、删除，以及沿用上一镜参考图。修改已确认镜头后自动标为待修改。
5. **动态预演**：定镜、局部光扫、渐显、推近、后拉、平移、上下摇、虚到实、首尾帧交叉淡化及多张动作帧。局部光扫可拖框、数值微调、选择矩形/椭圆并反转方向。
6. **导出与保存**：GIF、MP4 或 WebM、当前/结束帧 PNG、CSV 镜头表。V2 JSON 工程包含全部镜头和嵌入图片，可重新打开；兼容 V1 单镜工程。本地 IndexedDB 自动保存当前草稿。

“已生成”表示本镜已载入参考素材，可手动更改状态。状态不会触发 AI 生图。

### 脚本文本示例

```text
场景一：展厅
镜头01｜全黑背景，一束光扫过陶瓷杯。｜2秒｜特写｜光扫
旁白：让时间，慢一点。

镜头02｜人物走到展柜前停下。｜4秒｜中景｜向右平移
动作：走入，停下
备注：沿用同一产品。
```

### CSV 示例

```csv
镜号,场景,画面描述,动作,对白/旁白,时长,景别,机位,运镜,备注
01,展厅,一束光扫过杯子,,让时间慢一点,2,特写,正拍,光扫,背景保持静止
02,展厅,"人物走近,拿起杯子",拿起,,4,中景,侧拍,推近,保持产品一致
```

## 两项优先修复

- **GIF**：旧版示例有 24 个物理帧，但固定 RGB332 调色板使暗部丢失，独立解码只得到 6 个不同画面；2 秒镜头的帧间隔合计为 1.92 秒。现改为跨帧采样的自适应调色板、有效 LZW 字典和按总时长分配的帧延迟。内置示例经独立 Pillow 解码为 24 帧、22 个不同画面、2.00 秒、无限循环。
- **主体局部光扫**：保留原画面，以主体选区约束提亮层；光扫不会把整张背景一起渐显。修复选区抗锯齿边缘残留高光。编辑边框不会进入 GIF、视频或 PNG；预览和导出使用同一渲染器。

“估计主体范围”按背景色差取包围范围，**不是 AI 语义分割**。复杂背景应手动调整。强度设为 0 时画面保持原样。

## 测试方法

纯逻辑测试无需依赖：

```sh
node --test tests/core.test.mjs tests/gif.test.mjs
```

浏览器回归（安装测试依赖，不是运行应用的必要步骤）：

```sh
npm install
npx playwright install chromium
node tests/browser.mjs
python -m pip install Pillow==12.0.0
python tests/verify_gif.py
```

如使用 pnpm，可用 `pnpm install --frozen-lockfile`。`BROWSER_EXECUTABLE` 可指定已安装的 Chrome/Edge 路径；测试默认使用 4174 端口，`TEST_PORT` 可覆盖。

测试证据存放于忽略的 `test-results/`：桌面/手机截图、浏览器结果、真实下载的 GIF 和视频、独立 GIF 解码结果。GitHub 开发检查工作流仅运行测试、上传证据，不部署 Pages。

本次本地验证：**18 项逻辑测试、21 项浏览器检查通过**，GIF 的独立解码检查通过。浏览器使用 Windows Chrome。云端 CI 是否通过应以实际 Actions 运行结果为准。

## 范围与限制

- 当前拆镜是可解释的本地规则；**未接入大模型拆镜、AI 生图、AI 视频或语义主体分割**。文字生图入口提供提示词复制，再手动导入图片。
- PDF 直接解析、扫描件 OCR、旧版 `.doc` 不在本版范围。可先复制或转换为 TXT / DOCX。DOCX 会读取正文及表格中的段落，不解析批注、页眉和复杂版式。
- 首尾帧是交叉淡化，动作帧为连续图片过渡；单张图片不能可靠生成人物拿取、转身等真实动作。推拉平移为二维示意，不产生真实三维视差。
- GIF 为 480×270、12 fps，支持 0.5–30 秒。静止镜头或强度为 0 时帧画面可以相同。视频格式依赖浏览器，优先 MP4，必要时使用 WebM；录制期间请保持页面可见。
- “一致性资产库”、多镜连续播放、整片 MP4、PDF 分镜稿和团队协作留待后续。当前提供逐镜素材与上一镜参考图复用。
- 原图与草稿存于当前浏览器，不上传服务器。浏览器清理数据、不同端口/域名/设备不会共享草稿；重要项目请下载 JSON 工程备份。仅存一个当前草稿。每张图 ≤10 MB / 2400 万像素，工程导入 ≤80 MB，脚本文件 ≤8 MB / 文本 ≤25 万字。

仓库只含通用矢量示例，不包含真实产品和用户商业素材。
